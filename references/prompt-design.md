# 提示词卡片与提示词设计

## 截图是怎样做的

用户截图不是一张大图才能实现的效果：外层浅紫底 + 1px 淡紫虚线 + 圆角；顶部单独一栏“滑动查看完整提示词”，栏底同色虚线；内部是多段小字、较宽行距。右侧上下箭头是滚动提示，不是内容本身。
新 Skill 把文字做成真实 DOM。保留参考虚线结构，当前绿主题卡色统一为浅绿，Pro蓝用浅蓝。预览可滚动、可单独复制原始 prompt；公众号导出全部展开、标题为“完整提示词”，不放失效箭头/按钮。不能保证微信保留 overflow 滚动，因此不让滚动承担获取全文的唯一途径。
预览中的小字提高到 14px，以手机可读为先；不机械保留截图底部的大空白。

## 截图提示词的结构

截图里的 Rodin / Blender / Three.js 只是示例内容，不是此任务的执行要求。
其结构是：已有输入素材 → 主体还原约束 → 场景/环境 → 动态与镜头 → 画幅/时长/帧率 → 实现与证据 → 交付清单。
优点是具体约束和交付明确。可改进点是将“参考事实”与“推断”分开，写出最小验收条件，并规定能力不足时报告什么，不编造完成证据。

## 鲸选AI提示词配方（仅当用户要求创作/优化时使用）

1. 目标：完成什么、给谁使用，成功的可观察结果是什么。
2. 输入：资料、参考图、已有文件；哪些信息可以推断、哪些必须保留。
3. 边界：不要改什么、不能虚构什么；遇到未知项怎样处理。
4. 方法：必要操作顺序，不把实现细节无意义地锁死。
5. 输出：格式、文件、语言、尺寸/长度等确定要求。
6. 验收：逐条可检查的质量条件；实际验证与未验证项分开。

默认不改写用户已有提示词。若同时要优化，输出“原版”和“优化版”两份，清楚标注差别，不能用优化版暗中替换原版。

把主题选择从反复问答改为稳定规则；把“模型自由写样式”改为“模型生成语义 JSON + 确定性渲染”；把每段强制强调改为稀疏保真；把预览控件与文章内容隔离；把“看起来正常”与“微信实测成功”分开。
